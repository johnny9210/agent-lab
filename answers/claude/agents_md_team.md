# AGENTS.md에 더할 내용 (실습 2-C 예시 답안)

아래를 `AGENTS.md`의 '답변 메모 형식' 절 위에 넣는다.

```
## 팀 구성

메인 대화의 AI(**메인 에이전트**)는 일을 나눠 맡기고 결과를 모은다. 서브에이전트로 호출된 에이전트는 자기 지침(`.claude/agents/*.md`)을 따른다.

| 서브에이전트 | 이름 | 하는 일 | 결과 파일 |
|---|---|---|---|
| 펀드 표 조사 | `fund-scout` | 펀드의 상태, 추천 목록, 벤치마크, 환헤지, 보수 | `research/funds.md` |
| 문서 조사 | `doc-scout` | 공지, 운용보고서, 리서치 노트의 사실과 근거 | `research/docs.md` |
| 수치 분석 | `quant-scout` | 수익률, 벤치마크 대비 차이, 변동성, 최대 낙폭 | `research/quant.md` |
| 기준 검토 | `rule-checker` | 기준 14개 대조, 판정 | `review/rules.md` |
| 답변 작성 | `answer-writer` | 조사 결과로 답변 메모 작성 | `memo/memo.md` |
| 메인 에이전트 | 메인 대화 | 나눠 맡기고 결과를 보고 | 없음 |

## 답변 절차

사용자가 "답변 시작"이라고 하면 아래 순서로 진행한다.

1. 조사 서브에이전트 셋(`fund-scout`, `doc-scout`, `quant-scout`)을 **동시에** 호출한다. 각 서브에이전트에게 자기 결과 파일에 저장하라고 맡긴다. 셋이 모두 끝날 때까지 기다린다.
2. `answer-writer`를 호출해 조사 결과 세 파일로 `memo/memo.md`를 쓰게 한다. 자료를 처음부터 다시 뒤지지 말고 조사 결과의 값을 쓰라고 함께 적는다. 답변 메모는 여럿에게 나눠 맡기지 않고 `answer-writer` 혼자 쓴다.
3. `rule-checker`를 호출해 검토를 맡긴다. 끝날 때까지 기다린다.
4. `review/rules.md`의 판정이 '수정 필요'이면 `answer-writer`에게 피드백대로 `memo/memo.md`를 고치게 하고 3번으로 돌아간다. 최대 3번까지 한다. 3번을 넘기면 멈추고 남은 피드백을 사용자에게 알린다.
5. 판정이 '통과'이면 마지막 답에 질문별 '핵심 값' 줄과 '사람 승인' 절을 `memo/memo.md`와 똑같이 그대로 출력하고, 승인은 사람이 한다고 말한 뒤 멈춘다.

사용자가 단계를 나눠 시키면 그 단계만 한다.

## 메인 에이전트가 지킬 것

- 메인 에이전트는 답변 메모를 직접 쓰거나 고치지 않고, 자료 파일을 직접 뒤지지 않는다. 결과에 없는 것이 필요하면 그 서브에이전트에게 다시 맡긴다.
- 서브에이전트에게 일을 맡길 때는 읽을 것, 저장할 곳, 돌려받을 내용을 함께 적는다. 서브에이전트는 이 대화의 앞 내용을 모른다.
- `rule-checker`의 판정을 고치거나 건너뛰지 않는다.
- 승인은 사람이 한다. '사람 승인' 칸은 "대기 중"으로 둔다. 답변 메모를 PB나 고객에게 보내지 않는다.
```
